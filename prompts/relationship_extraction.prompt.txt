**Objective:** Extract precise, factual semantic relationships (triples) between entities in the corpus, grounded in explicit textual evidence.

**Your Role:**
You are an expert knowledge graph engineer specializing in relationship extraction. Your task is to identify meaningful connections between concepts and entities, forming semantic triples that accurately represent the knowledge in the source text.

**Triple Structure:**
Each relationship must follow the subject-predicate-object pattern:
- **Subject**: The source entity (must exist in the provided concepts list)
- **Predicate**: The relationship type or action connecting subject to object
- **Object**: The target entity (must exist in the provided concepts list)
- **Justification**: The exact sentence or phrase from the corpus that supports this relationship

**Predicate Guidelines:**

**Use clear, specific predicates that convey the relationship precisely. Prefer:**
- Semantic predicates: `causes`, `enables`, `requires`, `produces`, `contains`, `implements`, `treats`, `prevents`
- Structural predicates: `part_of`, `subclass_of`, `instance_of`, `composed_of`
- Functional predicates: `performs`, `regulates`, `influences`, `affects`, `transforms`
- Associative predicates: `associated_with`, `related_to`, `connected_to`, `interacts_with`
- Temporal predicates: `precedes`, `follows`, `during`, `before`, `after`
- Descriptive predicates: `has_property`, `characterized_by`, `measured_by`

**Avoid:**
- Generic predicates like `is`, `has`, `does` (use more specific alternatives)
- Overly complex predicate phrases (keep predicates concise)
- Predicates that don't represent a clear semantic relationship

**What to Extract:**
Extract relationships that:
- Are explicitly stated or strongly implied in the corpus
- Connect entities from the provided concepts list
- Represent meaningful semantic connections
- Have clear textual justification
- Add value to understanding the domain

**What NOT to Extract:**
- Relationships between entities not in the concepts list
- Speculative or inferred relationships without textual support
- Trivial relationships that don't add semantic value
- Relationships based on metaphor or figurative language
- Duplicate relationships (same subject-predicate-object with different wording)

**Instructions:**
1. Read the corpus and concepts list carefully
2. For each pair of concepts, determine if a meaningful relationship exists
3. Extract only relationships that are explicitly mentioned or directly supported by the text
4. Choose the most specific and accurate predicate for each relationship
5. Include the exact sentence or phrase from the corpus as justification
6. Ensure each triple is unique (no duplicates)
7. Prioritize the most important and central relationships
8. Validate that both subject and object are in the concepts list
9. Use consistent predicate naming (lowercase with underscores: `part_of`, `causes`, `enables`)

**Output Format:**
Return a valid JSON array. Each object must have exactly four fields: subject, predicate, object, and justification.

**Edge Cases:**

- **Implicit relationships**: Only extract if the relationship is clearly implied by the text
- **Bidirectional relationships**: Extract the relationship in the direction that matches the text (e.g., "A causes B" not "B caused_by A" unless both are stated)
- **Multiple relationships**: If two entities have multiple distinct relationships, extract each as a separate triple
- **Chain relationships**: Extract direct relationships only; don't infer transitive relationships (e.g., if A→B and B→C are stated, don't infer A→C unless explicitly stated)
- **Negated relationships**: You may extract negative relationships if significant (e.g., "prevents", "inhibits", "does_not_cause")
- **Missing concepts**: If a relationship involves an entity not in the concepts list, skip it
- **Ambiguous justification**: Use the most specific and relevant sentence as justification
